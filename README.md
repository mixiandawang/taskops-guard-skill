# TaskOps_AutoFill_Guard

> **让 AI 替你把一堆文档和链接变成任务清单，并且永远不替你按下"提交"。**

由 [@mixiandawang](https://github.com/mixiandawang) 维护 · MIT License

---

## 它解决什么问题

你手上有三样东西，但没有一张清单：

- 一份**通知文件**，写了四五件事，散在正文里
- 几个**链接**，点进去才发现要求藏在里面
- 一个**截止日期**，而且"材料不全者不予认定学分"

于是你花半小时整理，漏掉一项，或者**在最后一步填错表、点错按钮**。

这个技能把这三件事一起解决：自动读完所有材料 → 拆成结构化任务表 → 给出每项的步骤和工具 → 信息齐备后**帮你填好并暂存**——但从头到尾不会碰【提交】【支付】【发送】。

## 30 秒上手

不需要安装任何东西。打开 [`prompt-template.md`](prompt-template.md)，把里面横线以内的全文复制给**任意大模型**（ChatGPT / Claude / DeepSeek / 本地模型都行），后面接上你的材料：

```text
[粘贴模板全文]

---
我的材料：
- 附件：实习申请说明.pdf
- 链接：https://example.com/apply
- 我的情况：大三在读，想申请暑期实习
```

它会先给你**任务表**和**缺失项**，不会擅自行动。补齐后你发一句 `开始填报` 才进入执行。

## 前后对比：它到底做了什么

**输入**——一份普通的学院通知（节选）：

> 一、社会实践报告：不少于 3000 字，封面含姓名/学号/单位等，PDF 格式，命名"学号+姓名+报告"。
> 二、实践单位鉴定表：需单位盖章，扫描 PDF。模板下载：`https://example.invalid/form.docx`
> 三、个人总结：字数未作硬性规定。
> 四、请于 9 月 30 日前登录 `https://example.invalid/portal` 提交，需学号登录。

**输出**——技能跑完的结果（真实运行记录，非示意）：

| 编号 | 任务名称 | 要求 | 缺失 | 状态 |
|---|---|---|---|---|
| 1 | 社会实践报告 | 不少于 3000 字；封面 6 字段；PDF；命名 `学号+姓名+报告` | 姓名、学号、班级、单位、起止时间、题目 | `待确认` |
| 2 | 实践单位鉴定表 | 单位填写 + 盖章 + 扫描 | **下载链接不通**；需线下盖章 | `已卡堵` |
| 3 | 个人总结 | 字数未规定 → 建议 800–1500 字（默认值） | 无 | `可执行` |
| 4 | 系统提交 | 9 月 30 日前，学号登录 | **门户 URL 不通**；无登录凭证 | `已卡堵` |

它同时给出了三样你原本要自己想的东西：

- **两项卡阻已被识别**：两个 `example.invalid` 链接各尝试访问 1 次即熔断，未重试、未编造内容
- **一个默认值补位**："字数未规定" → 建议 800–1500 字，并明确标注这是默认值而非文档要求
- **一个隐藏提醒**："盖章"是物理动作，AI 代办不了，需要你线下办——**这类事通常最耗时**

**这就是价值**：不是替你写作业，而是**在你动手之前，把所有坑先标出来**。

## 三条硬性红线

这三条是这个项目存在的理由，也是它区别于普通"帮我填表"提示词的地方：

### 1. 暂存不提交

支持"暂存/保存草稿"的只暂存；不支持的只保持填写状态。
**永不点击【提交 / 发送 / 支付 / 确认订单 / 报名提交】**。执行结果一律以"请您核对无误后自行点击提交"收尾。

### 2. 单次尝试熔断

网页访问与工具调用**各限 1 次**。遇登录凭证缺失、验证码、付费墙、网络错误、超时，**立即止阻**并输出卡阻报告——不重试、不绕行、不猜测内容。

### 3. 质量把控

扫描件、截图、手写体必须走 OCR，并**强制标注 `（OCR 识别，可能有误）`**；模糊或冲突的内容严禁编造，一律列入缺失。

> ⚠️ **免责声明**：本规范是**行为约束**，不是技术隔离。它的安全性最终取决于宿主 harness 的权限边界与你自己的核对。任何自动填报结果都请人工复核后再提交。

## 能处理什么材料

| 材料类型 | 处理方式 |
|---|---|
| 通知 / 说明文档（txt / md / docx / pdf） | 直接提取要求，拆成任务 |
| **文档里的链接** | **强制穿透访问**，防止要求藏在链接深处 |
| 网页 / 在线表单 | 识别字段结构；分析阶段**不操作任何控件** |
| 截图 / 扫描件 / 手写体 | OCR 识别，结果强制标注可能有误 |
| 对话中提到的零散信息 | 进【已知信息池】，后续自动补全 |

## 典型场景

- 学院通知 / 实习申请材料，四五件事散在正文里
- 奖学金、竞赛、论文投稿的**多环节提交流程**
- 一堆链接和文档要整理成**可执行清单**
- 需要在网页表单上代填但**不敢让 AI 点提交**的场合

## 核心能力

| # | 能力 | 说明 |
|---|---|---|
| ① | **自动分析，不漏隐藏任务** | 同时提取显性要求与隐性已知信息；文档里的 URL **强制穿透读取** |
| ② | **结构化任务清单** | 六种状态可视化：`待确认`/`已明确`/`可执行`/`待处理`/`已完成`/`已卡堵` |
| ③ | **智能方案与建议** | 每项附【操作流程步骤】+【推荐工具】；参数缺失时给默认值补位并如实标注 |
| ④ | **动态决策与增量接收** | 自动区分"补充已有任务"与"追加新任务"，前者走轻量增量输出 |
| ⑤ | **已知信息池自动补全** | 按 `用户对话 > 文档/链接 > 默认值` 维护信息池；每个值标注来源（含 `（推断，请确认）`） |
| ⑥ | **安全防护与底层保障** | 暂存不提交 + 单次熔断 + OCR 强制标注（见上节） |

### 工作模式

```
[接收输入 (文档 / 链接 / 对话)]
        │
   ┌────┴─────┐
   ▼          ▼
[异常/阻碍]  [正常解析与规划]
   │          │
   │          ├──► (未收到"开始任务/开始填报") ──► Mode 2: ANALYSIS_MODE
   ▼          │
Mode 1: FUSE  └──► (收到"开始任务"或"开始填报") ──► Mode 3: EXECUTION_MODE
```

判定优先级 **Mode 1 > Mode 3 > Mode 2**，并区分两级熔断：

- **全局熔断**——输入源主体不可读 → 只输出卡阻报告
- **局部熔断**——部分链接失效但主体可读 → 照常输出完整分析，受阻项单独列出

## 安装

### 方式一：当提示词模板用（零安装，推荐先试）

见[30 秒上手](#30-秒上手)。

### 方式二：装成 Agent Skill

`SKILL.md` 采用通用的 Agent Skills 约定，把它放到对应 harness 的技能目录即可自动发现：

| harness | 安装位置 |
|---|---|
| DSH | 项目级 `.dsh/skills/` 或 `.agents/skills/`；用户级 `~/.dsh/skills/` |
| Claude Code | 项目级 `.claude/skills/`；用户级 `~/.claude/skills/` |
| 其他兼容 harness | 本质是"技能根目录下的一级子目录里放 `SKILL.md`" |

把 `skills/taskops-guard-skill/` 这个**整个子目录**复制过去：

```bash
cp -r skills/taskops-guard-skill ~/.dsh/skills/
```

Windows PowerShell：

```powershell
Copy-Item -Recurse skills\taskops-guard-skill $env:USERPROFILE\.dsh\skills\
```

### 方式三：直接读规范

[`skills/taskops-guard-skill/SKILL.md`](skills/taskops-guard-skill/SKILL.md) 本身是一份可读的行为规范，可以照着改写成你自己的版本。

## 文件结构

```
taskops-guard-skill/
├── README.md                          # 本文件
├── SKILL.md                           # 技能主体（与 skills/ 下内容一致）
├── prompt-template.md                 # 无 frontmatter 的提示词模板（供任意模型粘贴）
├── LICENSE                            # MIT
├── .gitignore
├── .gitattributes                     # 统一 LF 换行，防止 Windows 下 diff 全文件飘红
├── scripts/
│   └── validate.mjs                   # 自检：frontmatter 合法性 + 防止两份 SKILL.md 漂移
└── skills/
    └── taskops-guard-skill/
        └── SKILL.md                   # 可安装的 Skill 包（Agent Skills 约定）
```

**为什么有两份 `SKILL.md`**：根目录那份方便直接阅读，`skills/` 下那份符合 Agent Skills 的目录约定。两者内容必须一致，`scripts/validate.mjs` 会检查漂移。

## 自检

```bash
node scripts/validate.mjs
```

检查项：

1. `skills/taskops-guard-skill/SKILL.md` 存在且含合法 YAML frontmatter
2. `name` 符合正则 `^[a-z0-9]+(?:-[a-z0-9]+)*$`（**小写 kebab-case，这是硬性校验**）
3. 必填字段 `name` / `description` 非空
4. 未使用已废弃的 frontmatter 键（如 `modelInvocable`，会直接报错并导致技能被丢弃）
5. 两份 `SKILL.md` 正文一致（无漂移）

### 技能装了但没被发现的常见原因

| 现象 | 原因 | 修法 |
|---|---|---|
| 完全不出现，无任何报错 | `name` 里有大写字母或下划线 | 改成 `taskops-guard-skill` 这种小写 kebab-case |
| 完全不出现 | `SKILL.md` 位置放错 | 必须在技能根目录的**一级子目录**内 |
| 完全不出现 | 文件名不是 `SKILL.md` | 改成全大写 `SKILL.md` |
| 报了 frontmatter 错误 | 用了 `modelInvocable` 等旧键 | 改用 `disable-model-invocation` / `user-invocable` |

## 设计取舍与已知限制

- **不绑定具体工具名**：技能通过"能力映射表"引用宿主能力（网页抓取 / 联网搜索 / OCR / 文件读写），宿主缺少某项能力时按熔断处理，而不是猜测。因此它能在不同 harness 上运行，但**功能上限取决于宿主**。
- **无浏览器会话**：抓取工具通常不带登录态、不执行 JS，所以需要登录或前端渲染的页面必然触发熔断——这是设计预期，不是缺陷。
- **不做法律与合规判断**：代填第三方系统前，请先确认目标站点的服务条款允许自动化操作。
- **不安装任何软件、不启动任何服务、不代用户登录。**

### 开发记录

技能规范经过一轮真实场景测试，从测试中修出 4 个缺陷：

| 缺陷 | 问题 | 修法 |
|---|---|---|
| 熔断分级缺失 | 原规则"命中熔断即输出 Mode 1"，会导致因 2 个死链而拒绝分析整份可读文档 | 分为全局熔断与局部熔断 |
| 状态枚举不足 | 六种动作型中间态（如已盖章待扫描）无合法状态可用 | 新增 `待处理` |
| 来源标签缺失 | 无法区分"文档提取"与"上下文推断"，有编造风险 | 新增 `（推断，请确认）` 并加保守性约束 |
| 示例括号不配对 | `**【1】[任务名称】**` 渲染错乱 | 修正 |

详见 `git log`。

## 隐私与安全

本技能允许在用户**明确要求持久化**时，把【已知信息池】写入工作区的 `taskops-known-info.md`。该文件会包含姓名、学号、联系方式等个人信息：

- `.gitignore` **已默认忽略** `taskops-known-info.md` 与 `*.known-info.md`
- 如果你复制这个仓库另作他用，**请勿**在提交前删除该忽略规则
- 把个人信息交给任何 LLM 之前，请自行评估对方的数据政策

## 发布你自己的版本

> 面向 **fork 本仓库后二次发布**的使用者。只想使用本技能的话，无需阅读本节。

### 第一步：发布前的两道检查

```bash
# 1. 确认没有把个人信息/材料混进仓库（.gitignore 已挡 taskops-known-info.md）
git status --short

# 2. 自检技能包：frontmatter 合法性 + 两份 SKILL.md 防漂移
node scripts/validate.mjs
```

第 2 条拦的是**静默失败**：技能名带大写、`SKILL.md` 放错层级这类问题，harness 不会报错，只会当作技能不存在。

### 第二步：首次上传（仅第一次需要）

```bash
git init
git add .
git commit -m "feat: 我的任务分析规划与安全填报技能"
git branch -M main
git remote add origin <你的仓库地址>
git push -u origin main
```

执行前请在网页端新建一个**空仓库**（不要勾 Add README / .gitignore / License）。

> ⚠️ `git init` 与 `git remote add origin` 只需执行一次。若要同时推送 Gitee 镜像，请给第二个远端换个名字（例如 `gitee`）。

### 第三步：日常更新只需三条

```bash
git add .
git commit -m "改了什么"
git push
```

### Windows 用户建议的两项全局配置

```bash
# 提交身份（必填，否则无法 commit）
# 注意：user.email 会公开出现在每个 commit 上。
# 想隐藏真实邮箱，请用 GitHub 提供的匿名地址：
#   <你的数字ID>+<你的用户名>@users.noreply.github.com
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱或 noreply 地址"

# 中文路径不再显示成 \344\275\240 这种转义
git config --global core.quotepath false
```

若你的全局配置里存在 `http.sslVerify=false`，**建议在推送前删掉**：

```bash
git config --global --unset http.sslVerify
```

保持 TLS 校验关闭意味着推送流量可被中间人替换，对本项目（一段会被别人当指令执行的提示词）风险尤其高。
